## 概要

`config.json`は、mpmプラグイン本体の動作設定ファイルです。
リポジトリソース、グローバル設定、Discord Webhook通知、スケジュール自動更新などを定義します。

<Callout type="info" title="mpm.jsonとの違い">
mpmの設定ファイルは用途ごとに2つに分かれています。

- [`mpm.json`](/docs/format/mpm-config) — プロジェクト名・プラグイン依存関係（バージョン管理対象・チーム共有）
- [`config.json`](/docs/format/config)（このファイル） — リポジトリソース・Webhook・スケジュール（サーバー固有・バージョン管理対象外を推奨）

`config.json` はサーバーごとに異なる可能性のある設定（Webhookトークン、ローカルリポジトリパスなど）を扱うため、
通常は `.gitignore` に追加して個別管理することをおすすめします。
</Callout>

## ファイルの配置

`config.json`は`plugins/mpm/`ディレクトリに配置されます。

```
your-server/
├── plugins/
│   └── mpm/
│       ├── config.json    ← このファイル
│       ├── mpm.json       ← プロジェクト設定ファイル
│       ├── mpm-lock.yaml  ← 自動生成されるロックファイル
│       ├── repository/    ← ローカルリポジトリ
│       ├── metadata/      ← 個別プラグインの詳細情報
│       ├── cache/         ← HTTPメタデータキャッシュ
│       └── backups/       ← サーバーバックアップの保存先
└── ...
```

<Callout type="info" title="自動生成">
`plugins/mpm/config.json` が存在しない場合、mpm起動時にデフォルト値で自動生成されます。
</Callout>

## 基本構造

```jsonc title="plugins/mpm/config.json"
{
    "schemaVersion": 2,                  // 設定ファイルのスキーマ版数
    "repositories": [                    // リポジトリソース（優先順位順）
        {
            "type": "local",
            "path": "repository"
        },
        {
            "type": "remote",
            "url": "https://example.com/repository/",
            "headers": {
                "Authorization": "Bearer token"
            }
        }
    ],
    "settings": {
        "autoUpdate": false,
        "autoCheck": false,
        "lock": false,
        "tempDir": "temp",
        "githubToken": null,
        "webhook": {
            "enabled": false,
            "endpoints": []
        },
        "schedule": {
            "enabled": false,
            "cron": "0 4 * * *",
            "checkOnStartup": true
        },
        "cache": {
            "enabled": true,
            "metadataTtlSeconds": 300,
            "maxMetadataEntries": 200
        },
        "backup": {
            "enabled": true,
            "maxBackups": 5,
            "autoBackupOnUpdate": true,
            "autoBackupOnInstall": false
        }
    }
}
```

## フィールド詳細

### 📐 schemaVersion（スキーマ版数）

設定ファイルの構造の版数です。現在の版数は `2` です。

```json
{
    "schemaVersion": 2
}
```

- **デフォルト値:** `1`（記載がない場合は旧形式として扱われます）
- mpmが `config.json` を保存するたびに現行の版数が記録されるため、手で編集する必要はありません
- 版数が古いファイルは、サーバー起動時に自動で現行の構造へ移行されます

<Callout type="info" title="自動移行について">
版数の扱いと起動時の自動移行の詳細は
[スキーマ版数と自動移行](/docs/format/schema-migration) をご覧ください。

なお、かつて存在した `settings.schedule.dryRun` は廃止されました。
旧形式の `config.json` を読み込むと、自動移行の際にこの項目が取り除かれます。
</Callout>

### 📦 repositories（リポジトリソース）

プラグインのリポジトリファイルを取得するソースを定義します。
複数のソースを優先順位順（配列の先頭から）に指定できます。

#### ローカルソース

ローカルファイルシステムからリポジトリファイルを取得します。

```json
{
    "type": "local",
    "path": "repository"
}
```

- **type**: `"local"` を指定
- **path**: リポジトリディレクトリのパス（`plugins/mpm/` 配下の相対パス、デフォルト: `"repository"`）

**デフォルト値:**
```json
{
    "repositories": [
        {
            "type": "local",
            "path": "repository"
        }
    ]
}
```

#### リモートソース

リモートURLからリポジトリファイルを取得します。

```json
{
    "type": "remote",
    "url": "https://example.com/repository/",
    "headers": {
        "Authorization": "Bearer your-token",
        "Custom-Header": "value"
    }
}
```

- **type**: `"remote"` を指定
- **url**: リポジトリのベースURL
- **headers**: HTTPリクエストに追加するヘッダー（オプション）

#### 複数ソースの動作

複数のリポジトリソースを指定した場合、**優先順位順**（配列の先頭から）に検索します：

```json
{
    "repositories": [
        {
            "type": "local",
            "path": "repository"
        },
        {
            "type": "remote",
            "url": "https://official-repo.example.com/"
        },
        {
            "type": "remote",
            "url": "https://community-repo.example.com/"
        }
    ]
}
```

**動作:**
1. ローカルのリポジトリファイルを検索
2. 見つからなければ、公式リモートリポジトリを検索
3. それでも見つからなければ、コミュニティリポジトリを検索

### ⚙️ settings（グローバル設定）

mpm全体の動作設定を定義します。

```json
{
    "settings": {
        "autoUpdate": false,
        "autoCheck": false,
        "lock": false,
        "tempDir": "temp",
        "githubToken": null
    }
}
```

| フィールド | 説明 | デフォルト |
|-----------|------|-----------|
| `autoUpdate` | 現在は未使用（予約フィールド） | `false` |
| `autoCheck` | 現在は未使用（予約フィールド） | `false` |
| `lock` | 現在は未使用（予約フィールド） | `false` |
| `tempDir` | 現在は未使用（予約フィールド） | `"temp"` |
| `githubToken` | GitHub APIの認証トークン（レート制限回避用） | `null` |
| `webhook` | Discord Webhook通知の設定（後述） | デフォルト値 |
| `schedule` | スケジュール自動更新の設定（後述） | デフォルト値 |
| `backup` | 更新前のサーバー[バックアップ](/docs/commands/backup)設定（後述） | デフォルト値 |
| `cache` | HTTPメタデータキャッシュの設定（後述） | デフォルト値 |

<Callout type="warn" title="未使用の予約フィールド">
`autoUpdate` / `autoCheck` / `lock` / `tempDir` は、設定ファイルには書き出されますが現在の実装からは参照されていません。
値を変更しても動作は変わりません。

- ロックの有無は、プラグインごとの `metadata/*.yaml` の `settings.lock` だけで決まります。
  グローバル設定へのフォールバックは行われず、省略された場合は `false` として扱われます。
- 自動更新を行うかどうかは `schedule`（スケジュール自動更新）の設定で決まります。
- ダウンロード時の一時ファイルは `plugins/mpm/` の外、JVMのシステム一時ディレクトリに作成されます。
</Callout>

<Callout type="warn" title="githubTokenの扱い">
`githubToken` は個人アクセストークンなどの機密情報です。`config.json` を公開リポジトリにコミットしないよう、`.gitignore` に追加するか環境変数経由で管理することをおすすめします。
</Callout>

#### ⏰ schedule（スケジュール自動更新）

cron式を使用して、プラグインの自動更新をスケジュール実行できます。

```json
{
    "settings": {
        "schedule": {
            "enabled": true,
            "cron": "0 4 * * *",
            "checkOnStartup": true
        }
    }
}
```

| フィールド | 説明 | デフォルト |
|-----------|------|-----------|
| `enabled` | スケジュール自動更新の有効/無効 | `false` |
| `cron` | cron式（UNIX形式: 分 時 日 月 曜日） | `"0 4 * * *"` |
| `checkOnStartup` | サーバー起動時に更新チェックを行うか | `true` |

**cron式の例:**

| cron式 | 説明 |
|--------|------|
| `0 4 * * *` | 毎日午前4時に実行 |
| `0 3 * * 0` | 毎週日曜日の午前3時に実行 |
| `0 */6 * * *` | 6時間ごとに実行 |
| `30 2 1 * *` | 毎月1日の午前2時30分に実行 |

<Callout type="info" title="起動時チェック">
`checkOnStartup` が有効な場合、サーバー起動時に更新が必要なプラグインをチェックし、コンソールとDiscord Webhook（設定されている場合）に通知します。
起動時には更新チェックのみ行い、実際の更新は行いません。
</Callout>

<Callout type="info" title="自動更新の対象範囲">
スケジュール実行時に実際に更新されるのは、`mpm.json` のバージョン指定が `latest` または `tag:xxx` のプラグインだけです。
固定バージョン（例: `"1.2.3"`）や `pattern:` 指定のプラグインは、更新があってもチェックと報告のみを行い、更新は行いません。

`sync:` 指定のプラグインは、同期先（親）が自動更新された場合に限り、その新しいバージョンへ追従して更新されます。
また `/mpm lock` でロックされたプラグインは、バージョン指定の種類に関わらず更新されず、
「更新があるがロック中のためスキップした」旨がログに報告されます。

詳しくは [プラグインの更新](/docs/usage/update) をご覧ください。
</Callout>

<Callout type="info" title="タイムゾーン">
cron式の時刻はサーバーのJVMデフォルトタイムゾーンに基づきます。
必要に応じてサーバー起動時に `-Duser.timezone=Asia/Tokyo` で変更してください。
</Callout>

#### 🗄️ cache（HTTPメタデータキャッシュ）

バージョン一覧やプロジェクト情報の取得結果を、`plugins/mpm/cache/metadata/` に一時保存します。
`mpm outdated` や `mpm versions` のように同じ情報を繰り返し取得する操作で、
ネットワーク往復とAPIレート制限の消費を抑えるための仕組みです。

```json
{
    "settings": {
        "cache": {
            "enabled": true,
            "metadataTtlSeconds": 300,
            "maxMetadataEntries": 200
        }
    }
}
```

| フィールド | 説明 | デフォルト |
|-----------|------|-----------|
| `enabled` | メタデータキャッシュの有効/無効 | `true` |
| `metadataTtlSeconds` | キャッシュエントリの有効期間（秒）。`0` 以下を指定するとキャッシュを使用しません | `300` |
| `maxMetadataEntries` | 保持するメタデータエントリ数の上限。`0` 以下を指定すると上限なしになります | `200` |

<Callout type="info" title="自動的な整理">
キャッシュへの書き込みが一定回数（20回）に達するたびに、TTLを超過したエントリが削除されます。
さらにエントリ数が `maxMetadataEntries` を超えている場合は、最終更新が古いものから順に削除されます。
検索のようにキーワードごとに別エントリとなるリクエストがあるため、この上限で際限なく増えることを防いでいます。
</Callout>

<Callout type="info" title="キャッシュされないもの">
キャッシュ対象はメタデータのみです。プラグインのJARファイルはキャッシュされません。
現在のキャッシュ状況の確認や手動削除は [`mpm cache`](/docs/commands/cache) コマンドで行えます。
</Callout>

#### 🔔 webhook（Discord Webhook通知）

プラグインの管理イベントが発生した際に、Discord Webhookで通知を送信できます。
複数のエンドポイントを設定でき、各エンドポイントごとに通知するイベントを選択できます。

```json
{
    "settings": {
        "webhook": {
            "enabled": true,
            "endpoints": [
                {
                    "url": "https://discord.com/api/webhooks/xxxx/yyyy",
                    "events": {
                        "install": true,
                        "update": true,
                        "remove": true,
                        "uninstall": true,
                        "lock": true,
                        "unlock": true,
                        "outdated": true
                    }
                },
                {
                    "url": "https://discord.com/api/webhooks/aaaa/bbbb",
                    "events": {
                        "install": false,
                        "update": true,
                        "remove": false,
                        "uninstall": false,
                        "lock": false,
                        "unlock": false,
                        "outdated": true
                    }
                }
            ]
        }
    }
}
```

| フィールド | 説明 | デフォルト |
|-----------|------|-----------|
| `enabled` | Webhook通知のマスタースイッチ | `false` |
| `endpoints` | Webhookエンドポイントのリスト | `[]` |
| `endpoints[].url` | Discord WebhookのURL | — |
| `endpoints[].events.install` | プラグインインストール時の通知 | `true` |
| `endpoints[].events.update` | プラグイン更新時の通知 | `true` |
| `endpoints[].events.remove` | プラグイン管理対象除外時の通知 | `true` |
| `endpoints[].events.uninstall` | プラグインアンインストール時の通知 | `true` |
| `endpoints[].events.lock` | プラグインロック時の通知 | `true` |
| `endpoints[].events.unlock` | プラグインロック解除時の通知 | `true` |
| `endpoints[].events.outdated` | プラグイン更新可能検出時の通知 | `true` |

<Callout type="info" title="通知タイミング">
通知はイベントがキャンセルされずに処理された場合にのみ送信されます。
送信は非同期で行われるため、サーバーのパフォーマンスに影響はありません。
</Callout>

<Callout type="warn" title="Webhook URLの扱い">
Discord WebhookのURLはトークンを含む機密情報です。`config.json` を公開リポジトリにコミットしないように注意してください。
</Callout>

#### 💾 backup（サーバーバックアップ）

プラグインの更新を行う前に、`plugins/` ディレクトリ全体のバックアップを自動作成できます。

```json
{
    "settings": {
        "backup": {
            "enabled": true,
            "maxBackups": 5,
            "autoBackupOnUpdate": true,
            "autoBackupOnInstall": false
        }
    }
}
```

| フィールド | 説明 | デフォルト |
|-----------|------|-----------|
| `enabled` | バックアップ機能全体の有効/無効 | `true` |
| `maxBackups` | `/mpm backup cleanup` で保持するバックアップの件数 | `5` |
| `autoBackupOnUpdate` | 更新の前に自動でバックアップを作成するか | `true` |
| `autoBackupOnInstall` | 現在は未使用（予約フィールド） | `false` |

<Callout type="warn" title="autoBackupOnInstall は未使用です">
現在、`mpm install` / `mpm add` / `mpm adopt` などのインストール経路はバックアップを作成しません。
`autoBackupOnInstall` を `true` にしても、インストール前のバックアップは行われません。
インストール前にバックアップを取りたい場合は、`/mpm backup create` で手動作成してください。
</Callout>

<Callout type="info" title="スケジュール自動更新でのバックアップ">
スケジュール自動更新では、対象プラグインが何件あっても、1回の実行につきバックアップは1つだけ作成されます。
古いバックアップは自動では削除されないため、`/mpm backup cleanup` で定期的に整理してください。
</Callout>

## 使用例

### デフォルト構成（自動生成）

`plugins/mpm/config.json` が存在しない場合、mpm起動時に以下のデフォルト設定で自動生成されます：

```json
{
    "schemaVersion": 2,
    "repositories": [
        {
            "type": "local",
            "path": "repository"
        }
    ],
    "settings": {
        "autoUpdate": false,
        "autoCheck": false,
        "lock": false,
        "tempDir": "temp",
        "githubToken": null,
        "webhook": {
            "enabled": false,
            "endpoints": []
        },
        "schedule": {
            "enabled": false,
            "cron": "0 4 * * *",
            "checkOnStartup": true
        },
        "backup": {
            "enabled": true,
            "maxBackups": 5,
            "autoBackupOnUpdate": true,
            "autoBackupOnInstall": false
        }
    }
}
```

<Callout type="info" title="すべての項目が書き出されます">
mpmは設定を保存するとき、デフォルト値のままの項目も省略せずに書き出します。
そのため自動生成された `config.json` には、上記のようにすべての項目が含まれます。
不要に見える項目を手で削除しても、次回の保存時に再び書き戻されます。
</Callout>

### 複数リポジトリソースの構成

ローカルとリモートを併用する構成：

```json
{
    "schemaVersion": 2,
    "repositories": [
        {
            "type": "local",
            "path": "repository"
        },
        {
            "type": "remote",
            "url": "https://plugins.example.com/repository/"
        }
    ],
    "settings": {
        "autoUpdate": false
    }
}
```

### チーム共有用の構成

チームでリポジトリを共有し、認証付きリモートを使う場合：

```json
{
    "schemaVersion": 2,
    "repositories": [
        {
            "type": "local",
            "path": "repository"
        },
        {
            "type": "remote",
            "url": "https://team-repo.internal/plugins/",
            "headers": {
                "Authorization": "Bearer ${REPO_TOKEN}"
            }
        }
    ],
    "settings": {
        "githubToken": "ghp_xxxxxxxxxxxxxxxxxxxx"
    }
}
```

### Webhook + スケジュール自動更新の構成

毎日午前4時に自動更新を行い、Discord Webhookで結果を通知する構成：

```json
{
    "schemaVersion": 2,

            "type": "local",

        },
        "webhook": {
            "enabled": true,
            "endpoints": [
                {
                    "url": "https://discord.com/api/webhooks/xxxx/yyyy",
                    "events": {
                        "install": true,
                        "update": true,
                        "remove": false,
                        "uninstall": false,
                        "lock": false,
```

## 設定の再読み込み

設定変更後、サーバーを再起動せずに `/mpm reload` コマンドで設定を再読み込みできます。

`config.json` が壊れている、あるいは読み取れない場合、mpmはサーバーを止めずにデフォルト設定へ
フォールバックします。このとき `config.json` そのものには手を加えません。
`/mpm reload` を実行した場合は、成功ではなく黄色の警告として原因と対象パスがその場に表示されるため、
設定が無言で失われたと誤解することはありません。内容を修正してから再度 `/mpm reload` を実行してください。
リロード時にはリポジトリマネージャーとスケジューラーも新しい設定で再初期化されます。
