## 概要

`plugins/mpm/metadata/*.yaml`は、個別プラグインの詳細情報を保存するファイルです。
各プラグインに1つのファイルが作成され、プラグイン自体の情報とMPMによる管理情報の両方が記録されます。

<Callout type="info" title="自動生成と管理">
このファイルは`mpm add`コマンドなどによって自動的に生成されます。
一部のフィールドは手動で編集することもできますが、基本的には自動管理されます。
</Callout>

## ファイルの配置

```
your-server/
├── plugins/
│   ├── LuckPerms-Bukkit-5.4.102.jar
│   ├── Vault.jar
│   └── mpm/
│       ├── mpm.json
│       ├── mpm-lock.yaml
│       ├── repository/
│       └── metadata/
│           ├── LuckPerms.yaml     ← プラグインごとのメタデータ
│           ├── Vault.yaml          ← プラグインごとのメタデータ
│           └── EssentialsX.yaml   ← プラグインごとのメタデータ
└── ...
```

### 🔒 プラグイン名の制約

メタデータファイル名はプラグイン名から生成されます。
安全のため、プラグイン名には次の文字を含めることができません。

- パス区切り文字（`/`、`\`）
- 親ディレクトリ参照（`..`）
- ドライブ指定（`:`、例: `C:evil`）
- 制御文字（NUL 文字など）
- 空文字・空白のみの名前

なお、上記の文字を含まない場合でも、正規化したパスが
メタデータディレクトリの外を指す名前は拒否されます。

<Callout type="warn" title="不正なプラグイン名は拒否されます">
リポジトリファイルに `../../config` のような名前を指定した場合、
メタデータの読み書きはエラーとなり処理が中断されます。
これは意図しないディレクトリへのファイル書き込み（パストラバーサル）を防ぐための仕様です。
</Callout>

### 🗃️ 壊れたメタデータの退避

メタデータファイルが壊れていて読み込めない場合の扱いは、操作の種類によって異なります。

| 操作 | 動作 |
|------|------|
| `mpm install` / `mpm add` / `mpm adopt` | 原本を `.corrupt` に退避してから、新しいメタデータを作り直します |
| `mpm update`（一括・単体とも） | 何も変更せず、そのプラグインの更新を中断します |
| cron自動更新・`sync:` の連動更新 | 何も変更せず処理を中断します（無人実行のため作り直しません） |

`mpm update` は、メタデータを新しく作り直すのではなく既存の内容を書き換える操作のため、
退避も作り直しも行いません。壊れたメタデータを作り直したい場合は `mpm install` を実行してください。

<Callout type="info" title="未来のスキーマ版数のファイルは退避しません">
`schemaVersion` が現行版数より新しいメタデータは、壊れているのではなく
このmpmでは解釈できないだけです。これを退避して作り直すと、
[スキーマ版数と自動移行](/docs/format/schema-migration) のダウングレード防止が
退避経由で迂回されてしまいます。
そのため、この場合は退避も作り直しも行わず、操作そのものを中止します。
</Callout>

退避先のファイル名は `LuckPerms.yaml.corrupt` です。
既に同名の退避ファイルがある場合は `LuckPerms.yaml.corrupt.1`、`LuckPerms.yaml.corrupt.2` と
連番が振られるため、過去に退避したファイルが上書きされることはありません。

退避が実際に行われるのは、ダウンロードや検証を含むインストール処理がすべて成功し、
新しいメタデータを保存する直前になった時点です。
その手前で処理が失敗した場合、原本は退避されずにその場へ残ります。
これは「原本は退避済みなのに作り直したメタデータは保存されていない」という
メタデータが存在しない状態を作らないための仕様です。

退避の後で保存そのものが失敗した場合（書き込み権限がない、容量が足りない、
原子的なファイル置換に対応していない、など）は、退避した原本を元の場所へ戻します。
そのため、操作が失敗しても `metadata/<プラグイン名>.yaml` が消えてしまうことはありません。
万一その巻き戻しにも失敗した場合は、退避先の絶対パスを添えたエラーがコンソールへ出力されます。
表示されたファイル名から `.corrupt` 以降（`.corrupt.1` のように連番が付いている場合はそれも含めて）を
取り除き、`<プラグイン名>.yaml` という名前に戻してください。
`.corrupt` だけを取り除いて `LuckPerms.yaml.1` のような名前にすると、
mpmは `<プラグイン名>.yaml` しか読み込まないため、そのファイルは認識されません。

退避が行われるとコンソールに警告が出力され、退避先のパスが表示されます。

```log
[mpm] WARNING メタデータを読み込めないため退避して作り直します: LuckPerms (メタデータの読み込みに失敗しました: ...) -> /path/to/plugins/mpm/metadata/LuckPerms.yaml.corrupt
```

<Callout type="warn" title="lock などの設定は引き継がれません">
作り直されたメタデータの `settings` は初期値に戻ります。
`lock: true` を設定していた場合は、退避されたファイルの内容を確認したうえで
`/mpm lock` で設定し直してください。

なお、これは「メタデータが読み込めない」場合に限った話です。
メタデータが読める状態で `lock: true` が設定されている場合は、
`mpm add` / `mpm adopt` は設定を捨てて作り直すのではなく、その場で中止します
（`/mpm unlock <プラグイン名>` で解除してから実行してください）。
</Callout>

## 基本構造

```yaml title="plugins/mpm/metadata/LuckPerms.yaml"
# ファイルのスキーマ版数
schemaVersion: 2

# プラグイン基本情報（plugin.ymlまたはpaper-plugin.ymlから抽出）
pluginInfo:
  name: "LuckPerms"
  version: "5.4.102"
  main: "me.lucko.luckperms.bukkit.LuckPermsBukkitPlugin"
  description: "A permissions plugin for Minecraft servers"
  apiVersion: "1.13"
  author: "Luck"
  website: "https://luckperms.net"

# MPMによる管理情報
mpmInfo:
  repository:
    type: github
    id: LuckPerms/LuckPerms

  version:
    current:
      raw: "v5.4.102"
      normalized: "5.4.102"
    latest:
      raw: "v5.4.102"
      normalized: "5.4.102"
    lastChecked: "2025-01-15T10:30:00Z"

  download:
    url: "https://github.com/LuckPerms/LuckPerms/releases/download/v5.4.102/LuckPerms-Bukkit-5.4.102.jar"
    downloadId: "v5.4.102"
    fileName: "LuckPerms-Bukkit-5.4.102.jar"
    sha256: "abc123def456..."

  settings:
    lock: false
    autoUpdate: false
    autoCheck: false

  history:
    - version: "5.4.102"
      installedAt: "2025-01-15T10:30:00Z"
      action: "install"
```

## フィールド詳細

### 📐 schemaVersion

メタデータファイル自体の構造の版数です。現在の版数は `2` です。

```yaml
schemaVersion: 2
```

- **デフォルト値:** `1`（記載がない場合は旧形式として扱われます）
- mpmがメタデータを保存するたびに現行の版数が記録されるため、手で編集する必要はありません
- 版数が古いファイルは、サーバー起動時に自動で現行の構造へ移行されます

<Callout type="info" title="自動移行について">
`metadata/` 配下のYAMLは1ファイルずつ移行されます。
あるプラグインのメタデータの移行に失敗しても、他のファイルの処理やサーバーの起動は止まりません。

移行の仕組みの詳細は [スキーマ版数と自動移行](/docs/format/schema-migration) をご覧ください。
</Callout>

### pluginInfo

プラグインJARファイルの`plugin.yml`または`paper-plugin.yml`から抽出された情報です。

<Callout type="info" title="Bukkitプラグインとの違い">
Bukkitプラグインの場合は`BukkitPluginData`、Paperプラグインの場合は`PaperPluginData`として記録されます。
</Callout>

#### Bukkitプラグインの場合

```yaml
pluginInfo:
  name: "Vault"
  version: "1.7.3"
  main: "net.milkbowl.vault.Vault"
  description: "Vault is a Permissions & Economy API"
  apiVersion: "1.13"
  author: "Sleaker"
  website: "https://www.spigotmc.org/resources/vault.34315/"
```

#### Paperプラグインの場合

```yaml
pluginInfo:
  name: "ModernPlugin"
  version: "1.0.0"
  main: "com.example.ModernPlugin"
  description: "A modern Paper plugin"
  apiVersion: "1.20"
  bootstrapper: "com.example.ModernPluginBootstrap"
  loader: "com.example.ModernPluginLoader"
  author: "ExampleAuthor"
  website: "https://example.com"
```

### mpmInfo

MPMによる管理情報です。

#### repository

プラグインの取得元リポジトリ情報です。
`mpm.json`の`repository`フィールドと同じ形式です。

```yaml
mpmInfo:
  repository:
    type: github
    id: LuckPerms/LuckPerms
```

#### version

バージョン管理情報です。

##### current

現在インストールされているバージョン情報です。

```yaml
version:
  current:
    raw: "v5.4.102"          # リポジトリから取得した生のバージョン
    normalized: "5.4.102"     # 正規化されたバージョン
```

##### latest

最後にチェックした時点での最新バージョン情報です（キャッシュ）。

```yaml
version:
  latest:
    raw: "v5.4.103"
    normalized: "5.4.103"
```

##### lastChecked

最後にバージョンチェックを行った日時（ISO 8601形式）です。

```yaml
version:
  lastChecked: "2025-01-15T10:30:00Z"
```

#### download

ダウンロード情報です。`mpm-lock.yaml`の`download`フィールドと同じ形式です。

```yaml
mpmInfo:
  download:
    url: "https://github.com/LuckPerms/LuckPerms/releases/download/v5.4.102/LuckPerms-Bukkit-5.4.102.jar"
    downloadId: "v5.4.102"
    fileName: "LuckPerms-Bukkit-5.4.102.jar"
    sha256: "abc123def456..."
```

`sha256`は、インストール・更新時に計算された JAR のハッシュが自動的に記録されます。この値は次回以降のインストール時の整合性検証や、[`mpm verify`](/docs/usage/integrity)によるインストール済みプラグインの再検証に使用されます。

#### settings

プラグイン固有の設定です。

```yaml
mpmInfo:
  settings:
    lock: false          # バージョンロック
    autoUpdate: false    # 自動更新
    autoCheck: false     # 自動バージョンチェック
```

各フィールドは省略可能（`null`）です。省略された場合は `false` として扱われ、
`config.json` のグローバル設定へのフォールバックは行われません。

<Callout type="warn" title="グローバル設定へのフォールバックはありません">
ロックの有無は、このファイルの `settings.lock` だけで決まります。
`config.json` の `settings.lock` を `true` にしても、個別プラグインがロックされることはありません。

`autoUpdate` / `autoCheck` は現在の実装からは参照されていない予約フィールドです。
自動更新を行うかどうかは `config.json` の `schedule`（スケジュール自動更新）の設定で決まります。
</Callout>

#### history

プラグインのインストール・更新履歴です。

```yaml
mpmInfo:
  history:
    - version: "5.4.102"
      installedAt: "2025-01-15T10:30:00Z"
      action: "install"
    - version: "5.4.101"
      installedAt: "2025-01-10T09:00:00Z"
      action: "update"
    - version: "5.4.100"
      installedAt: "2025-01-05T08:00:00Z"
      action: "rollback"
```

| action | 説明 |
|--------|------|
| install | 新規インストール |
| update | バージョン更新 |
| rollback | ロールバック |

## 3つのファイルの関係

| ファイル | 役割 | 対象 |
|---------|------|------|
| mpm.json | プラグインの依存関係を宣言 | プロジェクト全体 |
| mpm-lock.yaml | インストールされたバージョンを記録 | プロジェクト全体 |
| metadata/*.yaml | プラグインの詳細情報を保存 | 個別プラグイン |

```
mpm.json
  ↓ mpm install
mpm-lock.yaml + metadata/LuckPerms.yaml
  ↓ プラグインJARからplugin.ymlを抽出
metadata/LuckPerms.yaml (pluginInfo更新)
```

## サポートされているリポジトリ

当プラグインでは、以下のリポジトリからのプラグインのインストールをサポートしています。

### GitHub

```yaml
mpmInfo:
  repository:
    type: github
    id: owner/repository  # owner/repo 形式
```

### Spigot

```yaml
mpmInfo:
  repository:
    type: spigot
    id: "34315"  # リソースID
```

### Modrinth

```yaml
mpmInfo:
  repository:
    type: modrinth
    id: plasmo-voice  # プロジェクトID
```

### Hangar

```yaml
mpmInfo:
  repository:
    type: hangar
    id: Plan  # プロジェクトID
```

### Jenkins

```yaml
mpmInfo:
  repository:
    type: jenkins
    id: https://ci.example.com/job/custom-plugin  # ジョブURL
```

### Local

```yaml
mpmInfo:
  repository:
    type: local
    id: /path/to/plugin.jar  # ファイルパス
```
