---
title: MineAuth連携
description: MineAuthが導入されている場合に有効化されるmpmのHTTP APIについて
---

mpmは、認証基盤プラグイン[MineAuth](https://github.com/morinoparty/MineAuth)が同じサーバーに導入されている場合、
プラグイン管理機能をHTTP API経由で操作できるように自動的にエンドポイントを登録します。

:::info
MineAuthはsoft dependencyとして扱われます。MineAuthが導入されていないサーバーでは連携機能が無効化されるだけで、
mpm自体の動作には一切影響しません。
:::

## 有効化の仕組み

mpmはMineAuthの`MineAuthApi`（v2）に対応しています。サーバー起動時、mpmは以下の順序でMineAuthとの連携を試みます。

1. `MineAuth` プラグインがサーバーに存在するか確認する
2. 存在する場合、Bukkitの`ServicesManager`経由で`MineAuthApi`インスタンスを取得する
3. 取得できた場合のみ、mpmのハンドラーを`mpm`名前空間で登録する

登録はall-or-nothingで行われます。いずれかのエンドポイントが検証に失敗した場合は何もマウントされず、
検証エラーの一覧を含む警告ログを出力したうえで連携を無効化します。いずれの場合もmpm本体の起動は継続します。
なお、登録されたエンドポイントはmpmプラグインの無効化時にMineAuth側で自動的に登録解除されます。

| 状態 | ログ | 結果 |
| --- | --- | --- |
| MineAuth未導入 | `MineAuth not found - HTTP API integration disabled` | 連携なしで起動 |
| APIサービス取得不可 | `MineAuth found but MineAuthApi service is unavailable - HTTP API integration disabled` | 連携なしで起動 |
| 登録検証エラー | `MineAuth integration failed (...): ... - HTTP API will be unavailable` | 連携なしで起動 |
| 連携成功 | `MineAuth integration enabled - N endpoints registered under /api/v1/plugins/mpm/` | エンドポイント有効化 |

## 認証・権限

登録されるすべてのエンドポイントは`@Authenticated`により認証必須です。
権限は、サーバーの状態を変更しない読み取り専用の操作と、状態を変更する操作とで分割されています。

| パーミッション | 対象 |
| --- | --- |
| `mpm.api.read` | 一覧・詳細・バージョン・履歴・依存関係・診断・検索など、読み取り専用のエンドポイント |
| `mpm.api.write` | 更新・インストール・アンインストール・ロック・バージョン切り替えなど、状態を変更するエンドポイント |
| `mpm.api` | 上記2つを子に持つ親パーミッション（後方互換のために維持されます） |

従来どおり `mpm.api` を付与した場合は、これまでと同じくすべてのエンドポイントにアクセスできます。
閲覧専用のトークンを発行したい場合は `mpm.api.read` のみを付与してください。

- **ユーザートークン**: 対応する権限を持つプレイヤーのトークンからのみアクセスできます。
- **サービストークン**: 各エンドポイントが `callers` にサービストークンを明示的に許可しているためアクセスできます。

:::info
`permission` はユーザープリンシパルに対して評価されます。
サービストークンは管理者が発行する信頼された資格情報であるため権限の評価対象外で、
エンドポイントごとの `callers` によってアクセスの可否が決まります。
したがって `mpm.api.read` / `mpm.api.write` の分割はユーザートークンに対して働き、
サービストークンについては `callers` がアクセス制御になります。

MineAuth v2では、旧APIにあった「サービストークンによる権限の暗黙的なバイパス」は廃止され、
エンドポイントごとに `callers` で明示的に許可する方式に変わりました。
mpmの全エンドポイントは、ユーザートークン・サービストークンの両方を許可するよう設定しています。
:::

## エンドポイント一覧

すべてのエンドポイントは `/api/v1/plugins/mpm/` を起点にマウントされます。

### 読み取り系（`mpm.api.read`）

| メソッド | パス | 説明 |
| --- | --- | --- |
| GET | `/plugins` | プラグイン一覧を取得する（`filter` で絞り込み可能） |
| GET | `/plugins/outdated` | 更新チェックの結果を取得する |
| GET | `/plugins/verify` | インストール済みプラグインの整合性を再検証する |
| GET | `/plugins/{name}` | プラグインの詳細情報を取得する |
| GET | `/plugins/{name}/versions` | 利用可能なバージョン一覧を取得する |
| GET | `/plugins/{name}/metadata` | メタデータ（ダウンロード元・sha256・履歴）を取得する |
| GET | `/plugins/{name}/history` | インストール履歴を取得する |
| GET | `/plugins/{name}/deps` | 依存関係情報を取得する |
| GET | `/doctor` | サーバーのプラグイン管理状態を一括診断する |
| GET | `/search` | リポジトリを横断してプラグインを検索する |
| GET | `/repositories` | 設定されているリポジトリソースの一覧を取得する |

### 書き込み系（`mpm.api.write`）

| メソッド | パス | 説明 |
| --- | --- | --- |
| POST | `/plugins/update` | 管理中の全プラグインを一括更新する |
| POST | `/plugins/{name}/update` | 指定したプラグインを更新する |
| POST | `/plugins/{name}/version` | 指定したプラグインを任意のバージョンに切り替える |
| POST | `/plugins/{name}/install` | 指定したプラグインをインストールする |
| POST | `/plugins/{name}/uninstall` | 指定したプラグインをアンインストールする |
| POST | `/plugins/{name}/lock` | 指定したプラグインをロックする |
| POST | `/plugins/{name}/unlock` | 指定したプラグインのロックを解除する |

## 読み取り系エンドポイント

### GET `/plugins`

プラグインを一覧取得します。クエリパラメータ `filter` で対象を絞り込めます。

| `filter` | 対象 |
| --- | --- |
| 省略 / `all` | mpmの管理下にあるプラグイン（既定値） |
| `managed` | mpmの管理下にあるプラグイン |
| `unmanaged` | mpmの管理下にないプラグイン（`plugins/` ディレクトリを走査した結果） |
| `outdated` | 更新が利用可能なプラグイン |
| `locked` | ロックされているプラグイン |

値は大文字小文字を区別しません。未知の値を指定した場合は `400 Bad Request` を返します。

```json title="レスポンス例"
[
  {
    "name": "QuickShop-Hikari",
    "status": "MANAGED",
    "isManaged": true,
    "currentVersion": "6.1.0.0",
    "latestVersion": "6.1.0.0",
    "isLocked": false,
    "isOutdated": false,
    "description": "A powerful and easy-to-use shop plugin",
    "author": "Ghost_chu",
    "repository": { "type": "MODRINTH", "id": "quickshop-hikari" },
    "lastChecked": "2026-08-29T00:00:00Z"
  }
]
```

`status` はエントリの由来を表します。

| `status` | 意味 |
| --- | --- |
| `MANAGED` | mpm.jsonに登録され、メタデータも正常に読み込めたプラグイン |
| `UNMANAGED` | mpmの管理下にないプラグイン |
| `METADATA_UNAVAILABLE` | mpm.jsonには登録されているが、メタデータファイルを読み込めなかったプラグイン |

:::info
`status` が `MANAGED` 以外のエントリは、バージョンやリポジトリの情報を持ちません。
これらのフィールドは内部のセンチネル文字列（`"unmanaged"` / `"unknown"`）ではなく `null` として返されます。
クライアントは `currentVersion` などがnullでありうる前提で実装してください。
:::

### GET `/plugins/outdated`

管理中のプラグインについて更新チェックを実行し、その結果を返します。
チェックに成功したプラグインは `outdated`、チェックに失敗したプラグインは `errors` に入ります。

実際に更新が必要かどうかは各エントリの `needsUpdate` で判定してください。
`currentVersion` と `latestVersion` の文字列比較では判定できません。
mpm内部の判定は正規化済みのバージョン同士を比較しているため、表記の揺れがあると結果が食い違います。

```json title="レスポンス例"
{
  "outdated": [
    {
      "name": "GriefPrevention",
      "currentVersion": "17.0.1",
      "latestVersion": "17.0.2",
      "needsUpdate": true
    }
  ],
  "errors": [
    {
      "name": "SomePlugin",
      "errorMessage": "Repository not found for SomePlugin"
    }
  ]
}
```

### GET `/plugins/verify`

インストール済み管理下プラグインのJARのsha256を計算し、メタデータに保存されたハッシュと照合します。
ネットワークアクセスは行いません。

```json title="レスポンス例"
[
  {
    "name": "QuickShop-Hikari",
    "status": "OK",
    "expectedSha256": "3f2a...",
    "actualSha256": "3f2a..."
  }
]
```

`status` は `OK` / `MISMATCH`（不一致）/ `NO_HASH`（ハッシュ未保存）/ `FILE_MISSING`（JARが見つからない）のいずれかです。

### GET `/plugins/{name}`

プラグインの詳細情報を取得します。リポジトリのプロジェクト情報APIを参照するため、ネットワークアクセスが発生します。

```json title="レスポンス例"
{
  "name": "QuickShop-Hikari",
  "slug": "quickshop-hikari",
  "source": "MODRINTH",
  "description": "A powerful and easy-to-use shop plugin",
  "homepage": "https://modrinth.com/plugin/quickshop-hikari",
  "license": "GPL-3.0",
  "downloads": 123456,
  "latestVersion": "6.2.0.0",
  "installedVersion": "6.1.0.0",
  "isLocked": false
}
```

### GET `/plugins/{name}/versions`

インストール可能なバージョンの一覧を新しい順に取得します。バージョン切り替えの選択肢を表示する用途を想定しています。

```json title="レスポンス例"
[
  { "raw": "v6.2.0.0", "normalized": "6.2.0" },
  { "raw": "v6.1.0.0", "normalized": "6.1.0" }
]
```

:::warning
バージョンはリポジトリ定義の**最初のソースからのみ**解決されます。
複数のダウンロード元が設定されたプラグインでは、2番目以降のソースのバージョンはこの一覧に現れません。
:::

:::info
上流リポジトリからのバージョン一覧の取得に失敗した場合は `503 Service Unavailable` を返します。
リクエスト自体は正当なため、時間を置いてから再試行してください。
:::

### GET `/plugins/{name}/metadata`

`metadata/<plugin>.yaml` に記録された情報を返します。ダウンロード元・sha256・インストール履歴を含みます。
メタデータが存在しない場合は `404 Not Found` を返します。

```json title="レスポンス例"
{
  "name": "QuickShop-Hikari",
  "description": "A powerful and easy-to-use shop plugin",
  "author": "Ghost_chu",
  "website": null,
  "repository": { "type": "MODRINTH", "id": "quickshop-hikari" },
  "currentVersion": "6.1.0.0",
  "latestVersion": "6.1.0.0",
  "lastChecked": "2026-08-29T00:00:00Z",
  "download": {
    "downloadId": "AbCdEfGh",
    "fileName": "QuickShop-Hikari-6.1.0.0.jar",
    "url": "https://api.modrinth.com/v2/version/AbCdEfGh/file",
    "sha256": "3f2a..."
  },
  "isLocked": false,
  "history": [
    { "version": "6.0.9.0", "installedAt": "2026-06-01T00:00:00Z", "action": "install" },
    { "version": "6.1.0.0", "installedAt": "2026-08-01T00:00:00Z", "action": "update" }
  ]
}
```

### GET `/plugins/{name}/history`

インストール履歴のみを古い順に取得します。詳細ページの履歴表示を想定した軽量なエンドポイントです。

```json title="レスポンス例"
[
  { "version": "6.0.9.0", "installedAt": "2026-06-01T00:00:00Z", "action": "install" },
  { "version": "6.1.0.0", "installedAt": "2026-08-01T00:00:00Z", "action": "update" }
]
```

### GET `/plugins/{name}/deps`

依存関係タブが1リクエストで描画できるよう、依存情報・依存ツリー・逆依存・依存経路をまとめて返します。
クエリパラメータ `soft=true` を指定すると、依存ツリーに `softdepend` も含めます。

```json title="レスポンス例"
{
  "name": "QuickShop-Hikari",
  "info": {
    "pluginName": "QuickShop-Hikari",
    "depend": ["Vault"],
    "softDepend": ["PlaceholderAPI"],
    "loadBefore": []
  },
  "tree": {
    "root": {
      "pluginName": "QuickShop-Hikari",
      "isInstalled": true,
      "isRequired": true,
      "children": [
        { "pluginName": "Vault", "isInstalled": true, "isRequired": true, "children": [] }
      ]
    },
    "missingRequired": [],
    "missingSoft": ["PlaceholderAPI"]
  },
  "reverseDependencies": [],
  "dependencyChains": []
}
```

### GET `/doctor`

依存関係・整合性・更新・ロックのドリフトなどをまとめて診断します。
`hasProblems` は、対処が必要な問題があるかどうかを表します（管理外プラグイン・更新可能・警告は判定に含みません）。

```json title="レスポンス例"
{
  "hasProblems": false,
  "missingDependencies": {},
  "hashMismatches": [],
  "fileMissing": [],
  "unmanagedPlugins": ["SomeOldPlugin"],
  "outdatedPlugins": [
    {
      "name": "GriefPrevention",
      "currentVersion": "17.0.1",
      "latestVersion": "17.0.2",
      "needsUpdate": true
    }
  ],
  "missingFromLock": [],
  "staleLockEntries": [],
  "warnings": []
}
```

### GET `/search`

複数のプラットフォーム（Modrinth / Hangar / SpigotMC / GitHub）を横断してプラグインを検索します。

| クエリパラメータ | 必須 | 説明 |
| --- | --- | --- |
| `q` | 必須 | 検索キーワード。省略または空文字の場合は `400 Bad Request` |
| `limit` | 任意 | 取得件数。既定値は10、上限は50（超える値は50に丸められます） |

```bash title="リクエスト例"
curl "https://<server>/api/v1/plugins/mpm/search?q=shop&limit=5" \
  -H "Authorization: Bearer <token>"
```

```json title="レスポンス例"
[
  {
    "source": "MODRINTH",
    "slug": "quickshop-hikari",
    "name": "QuickShop-Hikari",
    "description": "A powerful and easy-to-use shop plugin",
    "downloads": 123456,
    "url": "https://modrinth.com/plugin/quickshop-hikari"
  }
]
```

### GET `/repositories`

mpmがプラグイン定義を読み込むリポジトリソースを、優先順位順に返します。

```json title="レスポンス例"
[
  { "type": "remote", "identifier": "https://repo.morino.party/" },
  { "type": "local", "identifier": "plugins/mpm/repository" }
]
```

## 書き込み系エンドポイント

### POST `/plugins/update`

管理中のプラグインをすべて更新します。クエリパラメータ `force=true` を指定すると、
api-versionが非互換な場合でも強制的に更新します。

:::warning
このエンドポイントは管理下の**全プラグイン**をダウンロード・検証・配置するため、
プラグイン数によっては数分単位の時間がかかります。
処理が完了するまでレスポンスは返らず、進捗通知やジョブIDの仕組みも提供していません。
リバースプロキシやブラウザのタイムアウトに到達すると、クライアントは更新の成否を知る手段がなくなります。

そのため、**ブラウザからこのエンドポイントを直接呼び出すことは推奨しません。**
web consoleからは、プラグインごとの `POST /plugins/{name}/update` を利用してください。
一括更新が必要な場合は、タイムアウトを十分に長く設定したサーバー間の呼び出しか、
`mpm update` コマンドの利用を検討してください。
:::

```bash title="リクエスト例"
curl -X POST "https://<server>/api/v1/plugins/mpm/plugins/update?force=true" \
  -H "Authorization: Bearer <token>"
```

```json title="レスポンス例"
[
  {
    "pluginName": "GriefPrevention",
    "oldVersion": "17.0.1",
    "newVersion": "17.0.2",
    "success": true,
    "errorMessage": null
  }
]
```

### POST `/plugins/{name}/update`

指定したプラグインを更新します。パスパラメータ `name` にはプラグイン名を指定します。
プラグインが管理対象に存在しない場合は `404 Not Found` を返します。

更新対象に同期している `sync:` プラグイン（子孫）がある場合、親の更新後バージョンに追従して連動更新します。
同期の連鎖（A ← `sync:A` の B ← `sync:B` の C）にも伝播するため、
レスポンスは配列で、先頭が親の更新結果、以降が連動更新した子孫すべての結果となります。
リクエストで指定していないプラグインの結果も含まれる点に注意してください。

```json title="レスポンス例"
[
  {
    "pluginName": "MineAuth",
    "oldVersion": "0.2.30",
    "newVersion": "0.2.33",
    "success": true,
    "errorMessage": null
  },
  {
    "pluginName": "MineAuth-addon-griefprevention",
    "oldVersion": "0.2.30",
    "newVersion": "0.2.33",
    "success": true,
    "errorMessage": null
  },
  {
    "pluginName": "MineAuth-addon-luckperms",
    "oldVersion": "0.2.30",
    "newVersion": "0.2.30",
    "success": false,
    "errorMessage": "プラグインがロックされています",
    "skipped": true
  }
]
```

:::info
`success: false` かつ `skipped: true` の要素は、ロック中である・同期先が更新されなかった、といった
理由による意図的な据え置きであり、更新の失敗ではありません。
更新の失敗として利用者へ通知するのは `success: false` かつ `skipped` が `true` でない要素だけにしてください。
`skipped` が `false` の場合はレスポンスから省略されることがあるため、欠けていれば `false` として扱ってください。
:::

### POST `/plugins/{name}/version`

管理下のプラグインを、指定したバージョンに切り替えます。
アップグレードとダウングレードを区別せず、「このプラグインをバージョンXにする」という1つの操作として扱います。
切り替えに成功すると、mpm.jsonのバージョン指定は固定（`Fixed`）に書き換えられます。

リクエストボディはJSONで指定します。

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `version` | 必須 | 切り替え先バージョン。表記そのまま（raw）でも正規化後の表記でも解決を試みます |
| `force` | 任意 | `true` の場合、ロック済み・api-version非互換でも強制的に切り替えます（既定値: `false`） |
| `skipIntegrity` | 任意 | `true` の場合、整合性検証の不一致を無視して続行します（既定値: `false`） |

```bash title="リクエスト例"
curl -X POST "https://<server>/api/v1/plugins/mpm/plugins/QuickShop-Hikari/version" \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"version": "6.0.9.0"}'
```

```json title="レスポンス例"
{
  "pluginName": "QuickShop-Hikari",
  "oldVersion": "6.1.0.0",
  "newVersion": "6.0.9.0",
  "success": true,
  "errorMessage": null
}
```

`sync:` を指定しているプラグインは他プラグインへの追従が目的のため、切り替えを拒否し `409 Conflict` を返します。

切り替えたプラグインに追従している `sync:` プラグイン（子孫）があれば、切り替え後のバージョンへ連動更新します。
連動更新の結果はレスポンス本体ではなく `errorMessage` に要約として現れますが、
ロック中などで意図的に据え置かれた子（`skipped: true` に相当するもの）は失敗として数えないため、要約には含まれません。

指定されたバージョンは、まず表記そのままで解決を試み、見つからない場合は正規化して全バージョンと突き合わせます。
それでも一致しない場合は `400 Bad Request` を返します。
バージョン一覧の取得自体が上流リポジトリの障害で失敗した場合は `503 Service Unavailable` を返します。

### POST `/plugins/{name}/install`

指定したプラグインをダウンロードして `plugins/` ディレクトリに配置します。

```json title="レスポンス例"
{
  "name": "QuickShop-Hikari",
  "currentVersion": "6.1.0.0",
  "latestVersion": "6.1.0.0",
  "removedVersion": "6.0.9.0"
}
```

`removedVersion` は、更新に伴って古いjarファイルが削除された場合のみ値が入ります。

### POST `/plugins/{name}/uninstall`

指定したプラグインのjarファイルを削除します。反映にはサーバーの再起動が必要です。

```json title="レスポンス例"
{
  "name": "QuickShop-Hikari",
  "message": "Plugin 'QuickShop-Hikari' uninstalled successfully. Restart the server to apply changes."
}
```

### POST `/plugins/{name}/lock` / POST `/plugins/{name}/unlock`

プラグインのバージョンを固定（ロック）、またはその解除を行います。ロックされたプラグインは自動更新の対象外になります。

すでにロック済みのプラグインをロックした場合、またはロックされていないプラグインのロックを解除した場合は
`409 Conflict` を返します。

```json title="レスポンス例"
{
  "name": "QuickShop-Hikari",
  "isLocked": true,
  "message": "Plugin 'QuickShop-Hikari' has been locked."
}
```

:::warning
`force` クエリパラメータは `true` / `1` / `yes` / `on`（大文字小文字を区別しない）を真として扱います。
それ以外の値はすべて偽として扱われます。
:::

## エラーレスポンス

エラーはmpm内部のエラー種別に応じて、以下のHTTPステータスにマッピングされます。

| ステータス | 主な原因 |
| --- | --- |
| `400 Bad Request` | 不正な `filter` 値、空の `q` / `version`、存在しないバージョンの指定、未対応のリポジトリ種別 |
| `404 Not Found` | プラグイン・メタデータ・リポジトリ定義・mpm.json が見つからない |
| `409 Conflict` | 更新が既に実行中、ロック状態の不一致、`sync:` プラグインのバージョン切り替え、逆依存が存在する削除、api-version非互換 |
| `500 Internal Server Error` | ダウンロード失敗・整合性検証失敗・メタデータ保存失敗など、サーバー側の処理失敗 |
| `503 Service Unavailable` | 上流リポジトリ（Modrinth / Hangar / SpigotMC / GitHub）が一時的に応答しない |

ステータスはエラーメッセージの文字列ではなく、mpm内部のエラー型から決定されます。

### 400 と 503 の使い分け

`400 Bad Request` は、リクエストで指定された値そのものが解決できない場合に返されます。
バージョン指定の場合は、**リポジトリに存在しないバージョン名を指定した場合**がこれにあたります。

一方 `503 Service Unavailable` は、リクエストは正当であるものの、上流リポジトリがタイムアウトやレート制限などで
一時的に応答しなかった場合に返されます。**時間を置いて同じリクエストを再送すれば成功する可能性があります。**
クライアントは `503` を受け取ったら、少し待ってからリトライする実装にしてください。

### 409 の意味

`409 Conflict` は「同じリクエストをもう一度送っても解決しない」ことを表します。
たとえば更新ボタンの二重クリックでは `409` が返るため、クライアントは
「更新が既に実行中です」といった案内を表示できます。
