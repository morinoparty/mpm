プラグインのバックアップとリストアを行うコマンドです。

## 概要

`mpm backup` コマンドは、`plugins/` ディレクトリ全体（JARファイルと設定フォルダ）をZIP形式でバックアップします。
プラグインの更新前に `/mpm backup create` でバックアップを取っておくと、問題が発生した場合に以前の状態に戻すことができます。

## 使い方

### 手動バックアップの作成

```bash
/mpm backup create
```

現在の `plugins/` ディレクトリ全体のバックアップを作成します。
バックアップファイルは `plugins/mpm/backups/` に保存されます。

### バックアップ一覧の確認

```bash
/mpm backup list
```

作成されたバックアップの一覧を表示します。各バックアップには以下の情報が表示されます：

- **ID**: バックアップの識別子（リストア時に使用）
- **理由**: バックアップが作成された理由（UPDATE、INSTALL、MANUAL）
- **作成日時**: バックアップが作成された日時
- **サイズ**: バックアップファイルのサイズ

### バックアップからのリストア

```bash
/mpm backup restore <backupId>
```

<Callout type="warn">
リストアを実行すると、現在の `plugins/` ディレクトリの内容が上書きされます。
リストア後はサーバーの再起動が必要です。
</Callout>

### バックアップの削除

```bash
/mpm backup delete <backupId>
```

指定したバックアップを削除します。

### 古いバックアップのクリーンアップ

```bash
/mpm backup cleanup
```

保持期間（デフォルト: 7日）を過ぎた古いバックアップを自動的に削除します。

## バックアップディレクトリ構造

```
plugins/mpm/
└── backups/
    ├── index.json                         # バックアップインデックス
    ├── backup-2025-01-18-abc123.zip       # バックアップファイル
    └── backup-2025-01-17-def456.zip
```

## バックアップが作成されるタイミング

バックアップは `/mpm backup create` を実行したときにのみ作成されます（バックアップ理由: `MANUAL`）。
`mpm update` / `mpm rollback` / スケジュール自動更新 / `mpm install` などの操作では自動作成されません。
更新前に状態を残しておきたい場合は、事前に `/mpm backup create` を実行してください。

<Callout type="info" title="過去の自動バックアップについて">
以前のバージョンでは `mpm update` の前に自動でバックアップが作成されていました（理由: `UPDATE`）。
この機能は廃止されましたが、既に作成済みのバックアップは `/mpm backup list` に引き続き表示され、リストアも可能です。
</Callout>
